# Хмара S.A.D. – структура даних і правила доступу

Хмарна частина S.A.D. працює на Cloud Firestore (Firebase): проєкт `sad2-54cf9`, база `(default)` у регіоні `europe-central2` (Варшава).
Повний опис проєкту – у документі «S.A.D. – хмара й мобільний польовий журнал: проєкт».

## Файли

| Файл | Що це |
| --- | --- |
| `firestore.rules` | правила доступу – хто що бачить і може змінювати |
| `firestore.indexes.json` | індекс для вибірки нових значень за роком і часом |
| `firebase.json` | налаштування для Firebase CLI і локального емулятора |
| `tests/rules.test.js` | тести правил (власник, виконавець, сторонній, закритий рік, підробка автора й часу) |
| `../.github/workflows/cloud-rules.yml` | запуск тестів на GitHub при кожній зміні теки `cloud/` |

## Структура даних

```
users/{uid}                          профіль: ім'я
experiments/{expId}                  дослід
  ownerUid, ownerEmail               власник (керівник)
  code, name                         код і назва (у сліпому режимі назва порожня)
  mode: "open" | "blind"             відкритий чи сліпий облік
  status                             active / archive
  memberEmails: [..]                 запрошені виконавці (адреси малими літерами)
  closedYears: [2025, ..]            роки, облік яких закрито
  schemeSig, updatedAt               підпис поточної схеми, час зміни
  schemes/{sig}                      версія схеми з ділянками й маніфестом табличок
  indicators/{id}                    показник: назва, одиниця, тип (число / дата фази), рік
  values/{id}                        одне значення обліку
    plot, row, pos                   номер ділянки й рослина (клітинка) в ній: ряд і місце, як у журналі
    indicator, year                  показник і рік
    value                            число, дата «РРРР-ММ-ДД» або null разом із deleted: true
    authorUid, authorEmail           хто вніс
    serverTime, clientTime, device   час сервера, час на пристрої, пристрій
    schemeSig                        підпис схеми з QR, за якою внесено
    supersedes?                      id значення, яке це виправляє
```

Значення ніколи не змінюються: виправлення чи видалення – це новий запис із `supersedes`,
тож історія зберігається, а два значення від різних людей не перезаписують одне одного.

## Правила коротко

- Без входу – доступу немає. Виконавець має підтвердити адресу.
- Дослід бачать лише власник і запрошені (за адресою, регістр не важливий).
- Схему, показники, список виконавців і закриття року змінює лише власник.
- Значення вносять власник і виконавці – лише від свого імені, з часом сервера, не в закритий рік.
- Змінити внесене значення не може ніхто; видалити – лише власник.
- Ключ сліпого обліку в хмару не потрапляє взагалі.

## Тести

```
cd cloud
npm ci
npm test
```

Потрібні Node.js 22 і Java 21. На GitHub тести запускаються автоматично (Actions → «Хмара – тести правил доступу»).

## Публікація правил у ваш проєкт

Найпростіше – вручну: Firebase Console → Firestore → вкладка «Rules» → вставити вміст `firestore.rules` → «Publish».
Індекс: Firestore → «Indexes» → «Add index» → колекція `values`, поля `year` (за зростанням) і `serverTime` (за зростанням).
